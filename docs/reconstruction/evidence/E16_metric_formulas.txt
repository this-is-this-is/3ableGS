CLIP-S / CLIP-DS / Sem-CS for the weather-edited frames.

The three numbers the WeatherCity paper reports in Tables 1, 5 and 6, computed
directly from the image folders this repo produces:

    CLIP-S  = cos( f_img(I), f_img(I_hat) )
    CLIP-DS = cos( f_img(I_hat) - f_img(I), f_txt(T) )
    Sem-CS  = frequency-weighted IoU between seg(I_hat) and seg(I)

where I is ``images/raw/<frame>``, I_hat is ``images/<weather>/<frame>`` and T is
the weather prompt. The released code ships no metric implementation -- the README
points at WeatherEdit, whose public tree does not carry one either -- so this is
written from the formulas in the paper body.

Three things the paper leaves open. All are flags here, and whatever was used is
written into the output JSON so a number can be traced back to its setting:

``--clip_model``
    The paper names no checkpoint. CLIP-S and CLIP-DS both shift by a few points
    between ViT-B/32 and ViT-L/14, so a bare number is not comparable without it.

``--seg_model``
    The paper says "ConvNeXt-XL" and nothing else. UperNet+ConvNeXt-XL on ADE20K
    is the default; a Cityscapes-trained head gives a different (usually higher)
    Sem-CS because street scenes fall into fewer, larger classes.

``--prompt_mode``
    ``full`` uses the exact generation prompt from generate_weather_images.py.
    Those run 90-140 CLIP tokens and the text encoder truncates at 77, so part of
    the prompt silently does not reach the embedding -- the script says how much.
    ``short`` uses a one-line weather phrase that fits. Neither is "the" paper
    setting; ``full`` at least matches the text the images were generated from.

Also note CLIP-DS here follows the paper, which projects the image delta onto a
single text embedding f(T). The usual formulation (StyleGAN-NADA, InstructPix2Pix)
projects onto a text *delta*, f(T_target) - f(T_source). Values from the two are
not interchangeable; ``--directional_mode delta`` computes the standard variant
against a neutral source prompt for when a comparison against other papers is
wanted.

Fog reports CLIP-DS only, per the paper: fog removes so much of the scene that
content-preservation metrics stop meaning anything. CLIP-S and Sem-CS are still
computed and stored, just marked in the printed table; --fog_full prints them.
